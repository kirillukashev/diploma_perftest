## Аннотация (рабочая)

Работа посвящена разработке программного средства нагрузочного тестирования REST-сервисов на языке Python. Разработанный программный продукт **perftest** реализует декларативный подход на основе YAML-сценариев, шесть паттернов нагрузки (constant, ramp_up, spike, stepped, stress, soak), потоковую модель виртуальных пользователей через pycurl, экспорт метрик в Prometheus и визуализацию в Grafana. Экспериментальная оценка выполнена на тестовом Django-сервисе; зафиксирована точка насыщения при ~1 600 req/s. Предложены и обоснованы технические решения для корректного отображения перцентилей латентности и формы профилей нагрузки.

## Цель и задачи

**Цель:** разработать программное средство нагрузочного тестирования REST-сервисов с декларативным заданием сценариев, несколькими типизированными паттернами нагрузки, сбором перцентилей латентности и интеграцией с системами мониторинга, а также экспериментально верифицировать его работу на тестовом сервисе.

**Критерии достижения цели:**
- программный продукт запускает нагрузочные тесты по YAML-описанию без написания кода;
- реализованы все шесть паттернов нагрузки с верифицированными метриками;
- система обнаруживает точку насыщения тестируемого сервиса;
- метрики совпадают между тремя независимыми каналами (терминал, Prometheus, HTML-отчёт).

**Задачи:**

1. Провести обзор существующих программных средств нагрузочного тестирования и выявить их ограничения.
2. Сформулировать требования к разрабатываемому программному продукту.
3. Спроектировать архитектуру: YAML-конфигурация, потоковая модель VU, профили нагрузки, мониторинг, отчётность.
4. Разработать шесть паттернов нагрузки с единым абстрактным интерфейсом.
5. Разработать экспортер метрик в формате Prometheus с TTL-фильтрацией и скользящим окном перцентилей.
6. Разработать генератор HTML-отчётов с графиками и гистограммами.
7. Развернуть тестовый REST-сервис для изолированных замеров.
8. Экспериментально верифицировать программный продукт: провести тестирование с использованием всех шести профилей, зафиксировать точку насыщения, верифицировать корректность метрик через три независимых канала.

## Положения, выносимые на защиту

1. Декларативный YAML-формат позволяет описывать нагрузочные сценарии без написания кода и обеспечивает воспроизводимость тестов.
2. Потоковая модель на pycurl обеспечивает достаточную нагрузочную способность для I/O-bound REST-сервисов: программный продукт нагружает тестовый сервис до точки насыщения (~1 600 req/s), которая определяется архитектурой самого сервиса, а не генератора нагрузки.
3. Применение скользящего окна (30 секунд) для расчёта перцентилей и delta-RPS для расчёта пропускной способности позволяет отображать метрики, отражающие текущую фазу паттерна нагрузки, тогда как кумулятивные метрики скрывают эту динамику.

## Компоненты системы

| Компонент | Файл | Назначение |
| --- | --- | --- |
| Оркестратор | `resttest.py` | Парсинг, запуск тестов, стриминг метрик |
| Профили нагрузки | `load_profile.py` | 6 паттернов VU + `_vu_worker` |
| Экспортер Prometheus | `metrics_exporter.py` | HTTP `/metrics`, TTL 15 с |
| HTML-отчёты | `reporter.py` | Chart.js — перцентили, RPS, гистограммы |
| Парсер YAML | `parsing.py` | Разбор конфигурации |
| Функциональные тесты | `tests.py` | HTTP-тесты, валидаторы |
| Плагины | `plugin.py` | Реестр расширений |

> **Примечание о тестовом сервисе.** Django `runserver` — однопоточный WSGI-сервер; при ≥10–15 VU RPS выходит на плато ~1 600 req/s, а p99 резко растёт. Это намеренное ограничение демо-стенда: оно наглядно демонстрирует обнаружение точки насыщения — ключевую задачу нагрузочного тестирования.
