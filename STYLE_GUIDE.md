# Style Guide: Оформление ВКР

Источник: Положение о выпускной квалификационной работе студентов МФТИ  
(утв. приказом ректора от 21.01.2019 № 49-1, в ред. от 18.02.2026 № 576-1).  
ГОСТ-основа: ГОСТ 7.32-2017, ГОСТ Р 7.0.100-2018, ГОСТ Р 7.0.108-2022, ГОСТ Р 7.0.5-2008.

---

## 1. Структура работы

Обязательные элементы (в этом порядке):

1. Титульный лист (формируется в личном кабинете студента)
2. Аннотация (до 1 500 знаков: цели, результаты, рекомендации)
3. Содержание
4. Обозначения и сокращения (при необходимости)
5. Введение
6. Основная часть (главы и параграфы)
7. Заключение
8. Список использованных источников
9. Приложения (при необходимости)

**Ориентир по объёму (без приложений):**

| Уровень | Объём |
| --- | --- |
| Бакалаврская работа | 30–40 страниц |
| Дипломная работа | 40–50 страниц |
| Магистерская диссертация | 50–70 страниц |

**Требование оригинальности:** не менее 70% для бакалаврской/дипломной, не менее 80% для магистерской диссертации.

## 2. Параметры страницы

| Параметр | Значение |
| --- | --- |
| Формат | A4 (210 × 297 мм) |
| Поле левое | **30 мм** |
| Поле правое | **15 мм** |
| Поле верхнее | **20 мм** |
| Поле нижнее | **20 мм** |
| Межстрочный интервал | 1,5 |
| Шрифт | Times New Roman |
| Размер шрифта (основной текст) | 12–14 пт |
| Размер шрифта (названия глав и параграфов) | 14 пт |
| Размер шрифта (таблицы, подписи к рисункам) | 12 или 14 пт |
| Абзацный отступ | 1,25 см, одинаковый по всему тексту |
| Выравнивание текста | По ширине |
| Нумерация страниц | **По центру нижнего поля**; первая страница (титул) — без номера |

## 3. Заголовки

### Уровни

| Уровень | Что относится | Нумерация | Шрифт |
| --- | --- | --- | --- |
| H1 — Глава (раздел) | Введение, главы, заключение | `1`, `2`, `3` | 14 пт, жирный |
| H2 — Параграф (подраздел) | Разделы внутри главы | `1.1`, `1.2` | 14 пт, жирный |
| H3 — Пункт | Подразделы внутри параграфа | `1.1.1`, `1.1.2` | 12–14 пт, жирный |

### Правила оформления

- Слово «Глава» **не пишется** — только номер и название: `1 Теоретические основы`.
- Каждая глава начинается с **новой страницы**.
- В конце заголовка **точка не ставится**.
- Переносы слов в заголовке **недопустимы**.
- Заголовки **глав (H1)** — **по левому краю** или по центру (зависит от кафедры; уточни у руководителя).
- Заголовки **параграфов (H2, H3)** — **по центру**, строчными буквами, кроме первой прописной.
- Отступ от текста выше и ниже заголовка — стандартный интервал.

### В Markdown

```markdown
# 1 Теоретические основы нагрузочного тестирования   ← H1-глава
## 1.1 Понятие нагрузочного тестирования             ← H2-параграф (по центру)
### 1.1.1 Виды нагрузочного тестирования             ← H3-пункт (по центру)
```

Итого в Markdown: `#` = глава, `##` = параграф, `###` = пункт. Глубже не идём.

---

## 4. Стиль текста

- **Академический** стиль: без риторических вопросов, многоточий, лирических отступлений.
- Речь **от третьего лица**: «была реализована», «автором установлено», «в данной работе показано».
- **Настоящее время** — для описания текущего состояния области и цитирования работ других авторов.
- **Прошедшее время** — для собственных результатов: «система позволила обнаружить...».
- Каждая глава **заканчивается** отдельным параграфом «Выводы».

---

## 5. Введение

Обязательные элементы введения (в соответствии с требованиями МФТИ):

1. Обоснование актуальности темы
2. Определение объекта и предмета исследования
3. Цели и задачи работы
4. Перечень методов исследования
5. Краткая формулировка теоретической и практической значимости
6. **Научная новизна** (обязательна для «отлично»: «результаты обладают оригинальностью и новизной»)
7. Сведения об апробации результатов (публикации, конференции — при наличии)

---

## 6. Аннотация

Аннотация — отдельный структурный элемент перед Содержанием. Объём: **не более 1 500 знаков**.

Обязательно отражает:
- цели и задачи работы;
- полученные результаты;
- рекомендации, предложенные на основании работы.

---

## 7. Списки

### Маркированный список

Маркер — **тире (–)**, не дефис и не «bullet» (`•`).

```
– первый пункт;
– второй пункт;
– последний пункт.
```

### Нумерованный список

```
1) первый пункт;
2) второй пункт;
3) последний пункт.
```

---

## 8. Рисунки

- Нумерация: **сквозная** (`Рисунок 1`, `Рисунок 2`) или в пределах раздела (`Рисунок 1.1`). Уточни у руководителя.
- Подпись **после** рисунка, **по центру строки**: `Рисунок 1 – Архитектура системы`.
- Разделитель в подписи — **тире (–)**, не дефис.
- В тексте обязательна **ссылка** на каждый рисунок: «(см. рисунок 1)» или «в соответствии с рисунком 2».
- Рисунок и подпись — **по центру страницы**.

### В Markdown

```markdown
![Описание](../figures/architecture.png)

*Рисунок 1 – Архитектура системы нагрузочного тестирования*
```

---

## 9. Таблицы

- Нумерация: **сквозная** (`Таблица 1`) или в пределах раздела (`Таблица 1.1`).
- Название **над** таблицей, **слева, без абзацного отступа**, в одну строку с номером через тире:  
  `Таблица 1 – Сравнение инструментов нагрузочного тестирования`
- В тексте обязательна **ссылка**: «...данные приведены в таблице 1...».
- При переносе таблицы: «Продолжение таблицы 1» / «Окончание таблицы 1».

### В Markdown (подпись будет отформатирована скриптом постобработки)

```markdown
*Таблица 1 – Сравнение инструментов нагрузочного тестирования*

| Инструмент | Язык | Prometheus |
| --- | --- | --- |
| k6 | JS | Встроен |
| perftest | Python | Встроен |
```

> **Важно:** В текущих главах используется стиль `Таблица 2.1 — ...`. При финальной сборке скрипт постобработки выровняет подписи таблиц по левому краю согласно требованию МФТИ. Переходи на сквозную нумерацию `Таблица 1`, `Таблица 2` при финальном редактировании.

---

## 10. Листинги кода

- Листинги кода — иллюстративный материал; ёмкость: только значимые фрагменты.
- Подпись **после** блока, **по центру**: `Листинг 1 – Реализация VU-воркера`.
- Служебный, вспомогательный код выносится в **Приложения**.

---

## 11. Формулы

- Нумерация: сквозная `(1)`, `(2)` или в пределах раздела `(1.1)`, `(2.3)`.
- Номер — в **круглых скобках**, справа на уровне формулы.
- Пояснения — со слова **«где»** (без двоеточия, без абзацного отступа):

```markdown
$$
\rho = \frac{\lambda}{\mu} \tag{2.1}
$$

где $\rho$ — коэффициент загрузки, $\lambda$ — интенсивность поступления, $\mu$ — интенсивность обслуживания.
```

---

## 12. Библиографические ссылки

Оформляются в соответствии с **ГОСТ Р 7.0.5-2008**.

Допускается один из двух форматов:

**Ссылки в квадратных скобках** (рекомендуется для технических работ МФТИ):

```
[1], [2], [1, с. 45]
```

**Внутритекстовые** (если привычнее):

```
(Arlitt, Williamson, 1996) или (Arlitt, Williamson, 1996, p. 127)
```

Используй **один** тип ссылок во всей работе.

---

## 13. Список использованных источников

- Оформляется по **ГОСТ Р 7.0.100-2018** (не ГОСТ 7.1!).
- Электронные ресурсы — по **ГОСТ Р 7.0.108-2022**.
- Порядок: алфавитный — сначала кириллица, потом латиница; или по мере использования.
- Каждый источник должен быть упомянут в тексте.

### Примеры записей (ГОСТ Р 7.0.100-2018)

**Книга:**
```
Molyneaux I. The Art of Application Performance Testing. – Sebastopol : O'Reilly Media, 2009. – 194 p.
```

**Статья в журнале:**
```
Arlitt M. F., Williamson C. L. Web Server Workload Characterization: The Search for Invariants // ACM SIGMETRICS Performance Evaluation Review. – 1996. – Vol. 24, No. 1. – P. 126–137. – DOI: 10.1145/233008.233034
```

**Электронный ресурс:**
```
Grafana Labs. Grafana Documentation: Provisioning [Электронный ресурс]. – URL: https://grafana.com/docs/grafana/latest/administration/provisioning/ (дата обращения: 10.05.2026).
```

## 14. Критерии оценки «отлично» (МФТИ, Приложение 3)

Для получения «отлично» необходимо:

1. ✅ Обоснована актуальность на основе **аналитического осмысления** теории и практики в конкретной области.
2. ✅ Корректно поставлены цели и задачи, соответствующие теме и содержанию.
3. ✅ Выбранные методы соответствуют теме и решаемой проблеме.
4. ✅ **Результаты обладают оригинальностью и новизной** — явно сформулировать в Введении.
5. ✅ **Сформулированы перспективы и задачи дальнейшего исследования** — в тексте заключения.
6. ✅ Доклад структурирован; в заключительной части показаны перспективы.
7. ✅ Ответы на вопросы ГЭК чёткие.
8. ✅ Отзыв руководителя и рецензия без замечаний или с несущественными дискуссионными.

> **Ключевой пункт для «отлично»:** явная **научная новизна** в Введении. Для дипломной/магистерской без этого — максимум «хорошо».

## 15. Приложения

- Обозначаются прописными буквами кириллицы: **ПРИЛОЖЕНИЕ А**, **ПРИЛОЖЕНИЕ Б**, ...
- Слово «ПРИЛОЖЕНИЕ» — по центру верхней части страницы, прописными буквами.
- Заголовок приложения — с прописной буквы, полужирный, по центру.
- На каждое приложение — ссылка в тексте.

## 17. Быстрая памятка

| Что | Как в ВКР МФТИ |
| --- | --- |
| Поле левое | 30 мм |
| Поле правое | 15 мм |
| Поля верхнее/нижнее | 20 мм |
| Нумерация страниц | По центру **нижнего** поля |
| Заголовок главы H1 | Жирный, 14пт, с новой страницы |
| Заголовок параграфа H2 | Жирный, 14пт, **по центру** |
| Рисунок | `Рисунок N – Название` — после рисунка, по центру |
| Таблица | `Таблица N – Название` — над таблицей, **слева** |
| Формула | По центру, номер `(N)` справа |
| Список | Маркер `–` (тире) |
| Ссылки | `[N]` (квадратные скобки) или внутритекстовые |
| ГОСТ литературы | ГОСТ Р 7.0.100-2018 |
| Объём | 30–40 с. (бак.) / 40–50 с. (дипл.) / 50–70 с. (маг.) |
| Научная новизна | Явно в Введении — обязательно для «отлично» |
| Перспективы | В Заключении — обязательно для «отлично» |
