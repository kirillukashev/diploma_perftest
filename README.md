# Разработка инструмента нагрузочного тестирования REST API

## Краткое описание

Репозиторий содержит исходный код системы нагрузочного тестирования **perftest**, а также текст выпускной квалификационной работы по теме «Разработка инструмента нагрузочного тестирования REST API». Система реализует декларативный подход к нагрузочному тестированию на основе YAML-сценариев, шесть паттернов нагрузки, потоковую модель виртуальных пользователей через pycurl и интеграцию с Prometheus/Grafana.

## Предмет и цель работы

Предмет исследования — методы и инструменты нагрузочного тестирования HTTP-сервисов, модели параллельного выполнения запросов и подходы к сбору и визуализации метрик производительности.

Цель — спроектировать и реализовать инструмент нагрузочного тестирования REST API, обеспечивающий декларативное задание сценариев, несколько паттернов нагрузки, сбор перцентилей латентности и интеграцию с Prometheus/Grafana, и экспериментально оценить его работу на тестовом сервисе.

## Система нагрузочного тестирования

Исходный код находится в [`../perftest/`](../perftest/) (отдельный репозиторий).

### Ключевые возможности

| Функция | Описание |
|---|---|
| Декларативные YAML-сценарии | Тесты и бенчмарки описываются в YAML без написания кода |
| 6 профилей нагрузки | `constant`, `ramp_up`, `spike`, `stepped`, `stress`, `soak` |
| Виртуальные пользователи | Каждый VU — отдельный поток с curl-соединением (pycurl) |
| Метрики p50/p95/p99 | Скользящее окно 30 секунд для актуальных перцентилей |
| Delta-RPS | Запросов/сек за последние 5 секунд — отражает форму паттерна |
| Prometheus + Grafana | Встроенный HTTP-экспортер метрик, готовый docker-compose |
| HTML-отчёты | Самодостаточный файл с Chart.js — графики и гистограммы |
| Плагины | Кастомные компараторы, экстракторы, генераторы, агрегаторы |

### Профили нагрузки

| Паттерн | Форма | Назначение |
|---|---|---|
| `constant` | Фиксированные N VU | Baseline, проверка стабильности |
| `ramp_up` | Линейный рост | Поиск порога деградации латентности |
| `spike` | Резкий пик и спад | Flash-mob, внезапный пик трафика |
| `stepped` | Ступени VU | Точное определение точки насыщения |
| `stress` | Разгон → удержание → снижение | Максимальная ёмкость + восстановление |
| `soak` | Умеренная длительная нагрузка | Утечки памяти, деградация соединений |

### Технологический стек

| Слой | Технология |
|---|---|
| Язык и рантайм | Python 3.8+ |
| HTTP-клиент нагрузки | pycurl (libcurl) |
| Параллелизм | threading (VU = поток) |
| Конфигурация | YAML (PyYAML) |
| Метрики | Prometheus (exposition format) |
| Визуализация | Grafana (provisioning JSON/YAML) |
| HTML-отчёты | Chart.js |
| Тестовый сервис | Django + Tastypie, SQLite in-memory |
| Инфраструктура | Docker Compose |

## Ключевые технические результаты

### Точка насыщения Django dev-сервера

| VU | RPS | p50, мс | p95, мс | p99, мс |
|---:|---:|---:|---:|---:|
| 1 | ~840 | 1.2 | 1.8 | 2.1 |
| 5 | ~845 | 5.7 | 9.1 | 11.3 |
| 10 | ~1 200 | 8.3 | 14.6 | 19.4 |
| 20 | ~1 580 | 12.7 | 22.1 | 31.8 |
| 50 | ~1 620 | 30.4 | 58.9 | 89.2 |

При 20–50 VU RPS выходит на плато ~1 600 req/s — предел однопоточного Django `runserver`. Дальнейший рост числа VU увеличивает только очередь и латентность.

### Решённые инженерные задачи

| Проблема | Решение |
|---|---|
| Перцентили рисовались одной линией | Скользящее окно 30 секунд вместо кумулятивного расчёта |
| RPS не отражал форму паттерна | Delta-RPS (запросы за последние 5 секунд) вместо среднего |
| Гистограмма вырождалась из-за выбросов | Верхняя граница = p99 × 1.2 |
| Grafana-дашборд не загружался после рестарта | Строковый UID `"Prometheus"` + provisioning YAML |
| Метрики появлялись только в конце фазы | Периодический flush воркера каждые 50 запросов |

## Как воспроизвести

```bash
# 1. Клонировать и установить систему
git clone https://github.com/kirillukashev/perftest
cd perftest
pip install -e .

# 2. Поднять стек мониторинга
docker-compose up -d

# 3. Запустить тестовый Django-сервис
cd testapp && pip install django django-tastypie
python manage.py migrate
python manage.py runserver 0.0.0.0:8000

# 4. Запустить все профили нагрузки (~15 минут)
python -m perftest http://localhost:8000 examples/all-profiles.yaml --report report.html

# 5. Открыть Grafana: http://localhost:3000 (admin / admin)
# 6. Открыть отчёт: open report.html
```
